# Test lifecycle: graceful teardown

> Cross-references to sections elsewhere name their file; see `README.md` for the index.

The `dynamic_proxy` package's tests are self-contained (they spin up their own `httptest.Server` backends on random ports) — follow that pattern for new tests there.

The `proxyserver` package's tests each start real, in-process backend MCP servers and/or a real proxy instance (`doRunOn`) as goroutines bound to fixed ports, and share process-wide package-level vars (`triggeredRuntime`, `accessPolicyEngine`, `mcpServers`, `authConfig`, `internalSigner`) that `doRunOn` reassigns on every call. Every test that starts one of these must wait for it to be **fully** torn down — HTTP listener closed and background goroutines returned, not merely told to stop — before the test function returns, so the next test's `doRunOn` call doesn't reassign those vars out from under a goroutine that's still reading them:

- **`runProxyServerOn`** (`main.go`) runs an explicit `*http.Server` (not the package-level `http.ListenAndServe`, which ignores context cancellation) plus a `sync.WaitGroup` tracking the `monitor.Start(ctx)` goroutine; it doesn't return until the HTTP listener has closed (via `Shutdown`, triggered by `ctx.Done()`) *and* that background loop has returned. In production `Main` runs it under a `signal.NotifyContext` for SIGTERM/SIGINT, so the same teardown is what a Kubernetes pod stop (or Ctrl-C) triggers: the listener stops accepting connections, in-flight requests get up to 5s to finish, and the process exits 0 (a second signal kills it at once).
- **`doRunOn`** waits on the `runProxyServerOn` goroutine's `errChan` result after `ctx.Done()` fires, so `doRunOn` returning is a guarantee of full teardown, not just "asked to stop."
- **`runBackendServer`/`runMCPServer`** (`mcp_server_test.go`) follow the same pattern for in-process backend servers: an explicit `*http.Server` shut down on `ctx.Done()`, and `runMCPServer` returns a `*sync.WaitGroup` that's `Done` only once the listener has actually closed.
- **`startTestProxy`/`startTestBackend`** (`mcp_server_test.go`) are the shared entry points every `proxyserver` test uses: each starts its resource, waits briefly for a proxy to come up (failing the test immediately via `t.Fatalf` if it exits early), and registers a `t.Cleanup` that cancels `ctx` and waits for that resource's `sync.WaitGroup`/`errChan` before the test's cleanup is considered done. `integration_test.go`'s `TestProxyClient`, `session_proxies_test.go`'s `TestAllProxyCreation`/`TestProxyCreation`, `platform_servers_test.go`'s `TestPlatformServersOrchestration`, and `internal_auth_test.go`'s `TestInternalIdentityAssertion` all go through these two helpers — a new test that starts a backend or proxy should too.
- `TestAllProxyCreation`/`TestProxyCreation` (`session_proxies_test.go`) host their own backend servers on ports `:8082`/`:8083` (via `createServers()` + `startTestBackend`) rather than depending on another test's servers still being up.
- `platform_servers_test.go`'s `TestPlatformServersOrchestration` runs its own proxy instance via `startTestProxy(t, ctx, cancel, cfgPath, PLATFORM_TEST_PROXY_PORT)` — `cfgPath` being a `t.TempDir()` copy of `testdata/orchestration_test.cfg` with `natsUrl` injected — on `:8091`/`:8092`/`:8093`/`:8094` — distinct from `TestProxyClient`'s ports specifically so both tests coexist in the same `go test ./...` run without a bind collision.
- `internal_auth_test.go`'s `TestInternalIdentityAssertion` follows the same pattern on `:8095`/`:8096` (see "Internal identity assertions" (`auth.md`)).
- `configmap_test.go`'s `TestAdministratorRoleMapping` uses `:8120`. It connects with a per-session `bearerRoundTripper` token (`resource_metadata_test.go`) instead of `connectAsRole`: `connectAsRole` overwrites the shared `testToken` var, which silently switches every *earlier* session that test still holds to the newest role's token — fatal for a test that compares two roles side by side.
- `configmap_test.go`'s `TestAdminUpdatesAreValidated` uses `:8121`.
